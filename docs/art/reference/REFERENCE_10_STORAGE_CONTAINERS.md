# Reference 10 — Storage & Containers

## Purpose

Define the visual grammar for containers and storage infrastructure while keeping the family simple, modular and readable without texture dependence.

Approved visual companion:

- `visual/REFERENCE_10_STORAGE_CONTAINERS.png`

---

# Core language

Containers should communicate function primarily through:

- recognizable opening;
- obvious capacity volume;
- stable base or suspension;
- chunky lids/handles;
- clear empty/full/open/closed states;
- material identity through geometry and flat-color blocks.

Avoid ornate furniture language, tiny hardware and texture-led material identity.

---

# Core container families

Use a compact reusable vocabulary:

- crate;
- basket;
- coconut bowl/cup;
- bucket;
- simple storage box;
- jar/bottle;
- hanging basket;
- raised storage bin;
- large water vessel.

Variants should come from proportion, material family, lid/opening type, handle type and state rather than decorative detail.

---

# Storage evolution

Prefer visible progression such as:

```text
exposed ground pile
→ basket / crate
→ covered storage
→ raised storage
→ secured storage
```

Each stage should visibly solve a problem:

- organization;
- weather exposure;
- animal access;
- water protection;
- carrying convenience.

---

# State vocabulary

Useful shared states:

```text
empty / partial / full
open / closed
covered / exposed
dry / wet
intact / damaged / repaired
raised / hanging / ground
```

Fullness should be visible through a limited number of representative contents rather than dense piles.

---

# Food storage

Food-storage forms should read clearly from gameplay distance.

Prefer:

- fruit visible above basket rim;
- dry goods represented by a few large bundles/containers;
- hanging food with strong silhouette separation;
- covered storage using large leaf/cloth/wood cover shapes.

Do not model dozens of individual tiny food objects just to indicate fullness.

---

# Water containers

Water state should use:

- visible water plane when open;
- darker/glossier shared wet material state;
- clear empty/full difference;
- stable broad vessel opening.

Do not depend on transparent complex glass unless the object function specifically requires it.

---

# Animal protection

Physical solutions should remain legible:

- raise;
- hang;
- cover;
- close;
- surround/block.

Avoid bespoke creature-specific container designs when generic physical protection is sufficient.

---

# Repair and repurposing

Repairs should add history using broad visible pieces:

- replacement slat;
- rope reinforcement;
- simple patch;
- replacement handle;
- mismatched lid.

Found containers may be reused as planters, water collectors, hanging storage or utility vessels while preserving enough of their original identity to remain readable.

---

# Material policy

Default:

- shared flat-color materials;
- no unique texture maps;
- low slot count;
- broad metal/wood/fiber/ceramic/glass-like color differentiation;
- subtle shared wetness/weathering only when useful.

---

# Reference-sheet acceptance

A container family should be considered visually coherent when:

- each type reads from silhouette;
- open/closed and empty/full states are obvious;
- handles/lids are thick enough to survive gameplay distance;
- variants share one visual grammar;
- no variant becomes disproportionately ornate;
- storage evolution looks like increasing capability, not simply increasing decoration.
